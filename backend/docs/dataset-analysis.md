## 7. Open questions

**Not ambiguous — confirmed facts, recorded here so schema design doesn't
re-derive them:**

- Fraud rate: 20,663 / 590,540 = **3.499%** (`isFraud=1`), full-file count,
  not estimated. Informs the dev-subset sampler's `fraud_fraction`
  parameter and any future evidence-scoring baseline.
- `card1`–`card6`: composite "card fingerprint" (no real card number is
  ever disclosed by Vesta). `card4` (network: visa/mastercard/discover/
  amex) and `card6` (debit/credit) are categorical; `card1`,`card2`,
  `card3`,`card5` numeric-coded.
- `TransactionDT`: seconds offset from an undisclosed reference point, not
  a real calendar timestamp. Ordering/delta-between-transactions is valid;
  "what calendar date was this" is not answerable from this column alone.

**Genuinely ambiguous — AMBIGUOUS, REQUIRES REVIEW before schema design
commits to an answer:**

- Whether to load the ~340 `V*` engineered features as vertex/edge
  attributes at all. They are individually opaque (no public semantic
  mapping — see `docs/development-fallback-analysis.md` §2), many have
  50–95% null rates (§5 above), and their predictive value for *this*
  project's graph-based approach (vs. the flat tabular models the Kaggle
  competition was scored on) is unknown without testing. Recommendation
  to revisit at schema design time: exclude by default, keep the raw
  files as the source of truth, and add back only if a specific evidence
  query needs one.
- Whether `dist1`/`dist2` (65.8% / 92.2% null) are worth carrying as
  transaction attributes given the null rate, or should be dropped.
- `R_emaildomain` (68.2% null) — worth a relationship (recipient email) or
  too sparse to be useful graph structure.

**Confirmed NOT PRESENT in this source** (per this phase's explicit
instruction not to fabricate these — see `docs/development-fallback-analysis.md`):

- Fraud policy document
- Closed/confirmed case files
- The 20 official HHGoa benchmark cases
- Documented fraud typologies (five known patterns) — anything under this
  heading built later must be empirically derived from graph structure in
  *this* data and clearly marked `PROJECT-AUTHORED`, never presented as
  official.
