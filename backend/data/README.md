# Data directory

Nothing in here is generated by the application except the local SQLite
database and the vector store. **The source dataset is read-only** — no
script in this repository writes to `data/hhgoa/`.

## Layout

```
data/
├── hhgoa/              <- the HHGOA_IEEE dataset (NOT committed)
│   ├── transactions/
│   ├── cases/
│   ├── policies/
│   └── benchmark/
├── fraud_agent.db      <- SQLite, created on first run (NOT committed)
└── vector_store/       <- local embeddings cache (NOT committed)
```

The paths above are the defaults from `.env.example`. Override them with
`DATASET_ROOT`, `TRANSACTIONS_PATH`, `CASES_PATH`, `POLICIES_PATH` and
`BENCHMARK_PATH` if your copy of the dataset is laid out differently — the
loader reads these from config and does not hardcode any path.

## Installing the dataset

1. Place (or symlink) the HHGOA_IEEE dataset under `data/hhgoa/`.
2. Confirm the dataset's own README is present — the schema is derived
   from it, not guessed.
3. Profile it:

   ```bash
   python scripts/inspect_dataset.py
   ```

   This writes `docs/dataset-analysis.md` and
   `artifacts/dataset-profile.json`. It only reads.

The subdirectory names above are a starting guess based on the configured
paths. `inspect_dataset.py` walks whatever is actually there, so an
unexpected layout is reported rather than assumed — adjust the `.env`
paths once the real layout is known.

## Why the dataset is not committed

`.gitignore` excludes `data/hhgoa/**` — the dataset is large and is not
ours to redistribute. Every developer installs their own copy.
